HDR 画质优化解决方案 — Media3 ExoPlayer 1.9.0-rc01

核心问题：HDR 视频在 SDR 屏幕上显示发灰，画质低于电脑端播放器。

已完成的优化：clearViewportSizeConstraints() + setForceHighestSupportedBitrate(true) — 解决了分辨率降选和码率选择问题。

剩余问题：HDR→SDR 色调映射 (tone mapping) 未启用。

推荐方案：方案 A（自定义 Renderer + 强制 OpenGL Tone Mapping），无需额外依赖，利用项目已有的源码级 API。

当前状态

已完成 ✅ 已部署

优化项说明影响
clearViewportSizeConstraints() 禁用物理屏幕尺寸限制 4K 视频不再被降为 1080p
setForceHighestSupportedBitrate(true) 强制选最高码率轨道 多码率视频不再选中等码率

未完成 ❌ 待解决

问题原因表现
HDR→SDR 色调映射 ExoPlayer 仅在设备不支持 colorTransfer 时自动回退 tone mapping；支持 HDR 的设备不做转换，但 SDR 屏幕仍显示不正确 HDR 视频发灰、色彩平淡、对比度低

源码级架构分析

由于本项目是 Media3 源码级工程（非 Maven 依赖），我们可以直接访问和修改内部 API。通过源码分析发现：

HDR→SDR Tone Mapping 的完整调用链

ExoPlayer.setVideoEffects(List<Effect>)
  └─→ ExoPlayerImpl.setVideoEffects()
       ├─→ 反射检查 media3-effect 模块是否在 classpath  ❌ 不存在
       └─→ sendRendererMessage(MSG_SET_VIDEO_EFFECTS)
            └─→ MediaCodecVideoRenderer.setVideoEffects()
                 ├─→ videoEffects 字段被设置
                 └─→ enable() 时:
                      └─→ createPlaybackVideoGraphWrapper()
                           └─→ new PlaybackVideoGraphWrapper.Builder().build()
                                └─→ registerInput() 中判断 tone mapping:
                                     ├─ requestOpenGlToneMapping == true → 强制 SDR  ⭐
                                     ├─ HLG && API<34 && PQ支持 → 转 PQ
                                     ├─ colorTransfer 不支持 && API≥29 → 自动 SDR
                                     └─ 其他 → 保持原样 (HDR 直出)

关键发现

组件位置关键点
PlaybackVideoGraphWrapper libraries/exoplayer/.../video/ 内部有 requestOpenGlToneMapping 字段（行310），setRequestOpenGlToneMapping() 方法（行464）。 设为 true 时，registerInput() 会强制将输出设为 ColorInfo.SDR_BT709_LIMITED， 通过 OpenGL 执行 HDR→SDR tone mapping（行566-567）。
MediaCodecVideoRenderer libraries/exoplayer/.../video/ createPlaybackVideoGraphWrapper() 是 protected 方法（行977），可被子类覆盖。 这是注入 requestOpenGlToneMapping=true 的切入点。
ExoPlayerImpl.setVideoEffects() libraries/exoplayer/.../ 通过反射检查 androidx.media3.effect.SingleInputVideoGraph$Factory 是否在 classpath。 如果 media3-effect 模块不存在，会抛出 IllegalStateException。 但Effects pipeline 仅在 videoEffects != null 时创建 PlaybackVideoGraphWrapper（行888）。
media3-effect 模块 不存在于项目中 libraries/ 目录下只有 common, container, database, datasource, decoder, exoplayer, extractor, ui — 没有 effect 模块。

三个可选方案

方案 A：自定义 Renderer + 强制 OpenGL Tone Mapping 推荐

原理：继承 MediaCodecVideoRenderer，覆盖 createPlaybackVideoGraphWrapper()，在创建后调用 setRequestOpenGlToneMapping(true)。

不需要 media3-effect 模块 — 直接利用 PlaybackVideoGraphWrapper 内部已有的 OpenGL tone mapping 逻辑。但需要触发 effects pipeline 的创建条件。

实现步骤

  1. 创建自定义 ToneMappingVideoRenderer 继承 MediaCodecVideoRenderer
  2. 覆盖 createPlaybackVideoGraphWrapper()，在返回前调用 setRequestOpenGlToneMapping(true)
  3. 创建自定义 RenderersFactory，用 ToneMappingVideoRenderer 替换默认视频渲染器
  4. 在 PlayerActivity 中使用自定义 RenderersFactory

关键代码

// ToneMappingVideoRenderer.java
public class ToneMappingVideoRenderer extends MediaCodecVideoRenderer {

    public ToneMappingVideoRenderer(Context context) {
        super(context, MediaCodecSelector.DEFAULT);
    }

    @Override
    protected PlaybackVideoGraphWrapper createPlaybackVideoGraphWrapper(
            Context context, VideoFrameReleaseControl videoFrameReleaseControl) {
        PlaybackVideoGraphWrapper wrapper = super.createPlaybackVideoGraphWrapper(
                context, videoFrameReleaseControl);
        // 强制启用 OpenGL HDR→SDR tone mapping
        wrapper.setRequestOpenGlToneMapping(true);
        return wrapper;
    }
}
// ToneMappingRenderersFactory.java
public class ToneMappingRenderersFactory extends DefaultRenderersFactory {

    public ToneMappingRenderersFactory(Context context) {
        super(context);
        setExtensionRendererMode(EXTENSION_RENDERER_MODE_ON);
        setEnableDecoderFallback(true);
    }

    @Override
    protected void buildVideoRenderers(
            Context context,
            @ExtensionRendererMode int extensionRendererMode,
            MediaCodecSelector mediaCodecSelector,
            CustomDrmSessionManager.Provider drmSessionManagerProvider,
            long allowedVideoJoiningDurationMs,
            Handler eventHandler,
            VideoRendererEventListener videoRendererEventListener,
            ArrayList<Renderer> out) {
        out.add(new ToneMappingVideoRenderer(context));
        super.buildVideoRenderers(context, extensionRendererMode,
                mediaCodecSelector, drmSessionManagerProvider,
                allowedVideoJoiningDurationMs, eventHandler,
                videoRendererEventListener, out);
    }
}
// PlayerActivity.java - initializePlayer() 中替换
// 原来：
DefaultRenderersFactory renderersFactory = new DefaultRenderersFactory(this)
    .setExtensionRendererMode(...)
    .setEnableDecoderFallback(true);

// 改为：
ToneMappingRenderersFactory renderersFactory = 
    new ToneMappingRenderersFactory(this);
⚠️ 注意：此方案需要触发 PlaybackVideoGraphWrapper 的创建。 源码中 videoEffects != null 是创建条件（行888）。 需要在 prepare() 前调用 player.setVideoEffects(ImmutableList.of())（空 list）来触发 effects pipeline。 但 setVideoEffects() 会反射检查 media3-effect 模块——如果不添加该模块会抛异常。

解决方案：同时添加 media3-effect 模块到项目（从 upstream 拉取），或修改 ExoPlayerImpl.setVideoEffects() 移除反射检查。

优缺点

优点缺点
  • 利用项目已有的 OpenGL tone mapping 内部实现
  • API≥29 广泛支持
  • 视觉效果好（OpenGL tone mapping 质量较高）
  • 无需额外第三方库
  • 需要添加 media3-effect 模块或修改 ExoPlayerImpl
  • 使用了 @UnstableApi 内部 API
  • 可能引入轻微性能开销（OpenGL 处理）

方案 B：添加 media3-effect 模块 + setVideoEffects API 标准方案

原理：从 Media3 upstream 拉取 libraries/effect 模块，添加到项目构建中，然后通过标准的 setVideoEffects() API 启用 effects pipeline。

实现步骤

  1. 从 androidx/media 仓库拉取 libraries/effect 目录
  2. 在 core_settings.gradle 添加 include ':lib-effect'
  3. 在 media/build.gradle 添加 implementation project(modulePrefix + 'lib-effect')
  4. 在 PlayerActivity.initializePlayer() 中 prepare() 前调用： 
    player.setVideoEffects(ImmutableList.of());
  5. 同时使用方案 A 的自定义 Renderer 来设置 requestOpenGlToneMapping=true

优缺点

优点缺点
  • 使用标准 API，不修改内部代码
  • 未来可添加更多 video effects
  • Google 官方推荐路径
  • 需要拉取并集成 media3-effect 模块
  • 增加 APK 体积
  • 需要确认版本兼容性（当前 1.9.0-rc01）
  • 仍需自定义 Renderer 来强制 tone mapping

方案 C：修改 ExoPlayerImpl 移除反射检查 + 自定义 Renderer 最小改动

原理：直接修改源码，移除 ExoPlayerImpl.setVideoEffects() 中的反射检查，使空 effects list 能正常传递到 renderer 以触发 PlaybackVideoGraphWrapper 创建。

关键修改

// ExoPlayerImpl.java - setVideoEffects() 修改前:
public void setVideoEffects(List<Effect> videoEffects) {
    verifyApplicationThread();
    try {
        Class.forName("androidx.media3.effect.SingleInputVideoGraph$Factory")
            .getConstructor(VideoFrameProcessor.Factory.class);
    } catch (ClassNotFoundException | NoSuchMethodException e) {
        throw new IllegalStateException("Could not find required lib-effect dependencies.", e);
    }
    sendRendererMessage(TRACK_TYPE_VIDEO, MSG_SET_VIDEO_EFFECTS, videoEffects);
}

// 修改后（移除反射检查）:
public void setVideoEffects(List<Effect> videoEffects) {
    verifyApplicationThread();
    sendRendererMessage(TRACK_TYPE_VIDEO, MSG_SET_VIDEO_EFFECTS, videoEffects);
}
// PlayerActivity.java - prepare() 前添加:
player.setVideoEffects(ImmutableList.of());

同时仍需方案 A 的自定义 Renderer 来设置 requestOpenGlToneMapping=true。

优缺点

优点缺点
  • 改动最小，不需要额外模块
  • 不需要从 upstream 拉取代码
  • 修改了 Media3 框架内部代码，升级时需注意合并
  • 违反了 setVideoEffects 的 API 契约
  • 运行时可能在 PlaybackVideoGraphWrapper 内部因缺少 effect 模块类而崩溃

推荐方案：A + B 组合

最佳实践：方案 B（添加 media3-effect 模块）+ 方案 A（自定义 Renderer 强制 tone mapping）

理由：

  1. 添加 media3-effect 模块使 setVideoEffects() API 正常工作，不违反框架的 API 契约，PlaybackVideoGraphWrapper 内部所需的 effect 类（如 SingleInputVideoGraph$Factory）也能在运行时找到。
  2. 自定义 Renderer覆盖 createPlaybackVideoGraphWrapper()，调用 setRequestOpenGlToneMapping(true)，这是唯一能在设备支持 HDR colorTransfer 时强制执行 tone mapping 的方式。
  3. 仅调用 setVideoEffects(ImmutableList.of()) 只会创建 effects pipeline 但不会自动 tone map（因为设备支持 colorTransfer 时走 "保持原样" 分支）。必须配合自定义 Renderer。

后续建议

1. 验证当前优化效果

在实施 HDR tone mapping 前，建议先用 SDR 高分辨率视频验证已有的 clearViewportSizeConstraints() 和 setForceHighestSupportedBitrate(true) 是否生效。准备一段 4K SDR 视频播放，对比修改前后的画质差异。

2. HDR 视频测试素材

准备 HDR10/HLG 测试视频验证 tone mapping 效果：

  • HDR10 (PQ/ST2084) — 最常见的 HDR 格式
  • HLG — BBC/NHK 开发的 HDR 格式
  • Dolby Vision — 需要额外解码器支持

3. 性能监控

启用 tone mapping 后，OpenGL 处理会增加 GPU 负载。建议在低端设备上测试：

  • 播放 4K HDR 视频时的丢帧率
  • CPU/GPU 占用率变化
  • 电池消耗影响

如果性能不达标，可以考虑添加 "仅在 SDR 屏幕上启用 tone mapping" 的运行时判断逻辑。

4. 自动检测 SDR 屏幕

可以在自定义 Renderer 中添加运行时判断，仅在 SDR 屏幕上启用 tone mapping：

@Override
protected PlaybackVideoGraphWrapper createPlaybackVideoGraphWrapper(
        Context context, VideoFrameReleaseControl videoFrameReleaseControl) {
    PlaybackVideoGraphWrapper wrapper = super.createPlaybackVideoGraphWrapper(
            context, videoFrameReleaseControl);
    
    // 仅在 SDR 屏幕上强制 tone mapping
    Display display = ((WindowManager) context.getSystemService(Context.WINDOW_SERVICE))
            .getDefaultDisplay();
    boolean isHdrDisplay = display.isWideColorGamut() 
            && (display.getHdrCapabilities() != null 
                && display.getHdrCapabilities().getSupportedHdrTypes().length > 0);
    
    if (!isHdrDisplay) {
        wrapper.setRequestOpenGlToneMapping(true);
    }
    return wrapper;
}
